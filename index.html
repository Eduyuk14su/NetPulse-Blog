O PROBLEMA

Uma rede raramente falha sem dar sinais.

Latência crescente, perda de pacotes e instabilidade podem anteceder uma degradação do serviço. Vamos investigar como modelos baseados em árvores podem transformar esses indicadores em uma classificação de risco — sem confundir demonstração com validação operacional.

01 MODELO BASELINE

Árvore de Decisão

Uma sequência de perguntas divide os dados até chegar a uma previsão.

Imagine que o NetPulse recebe uma medição de rede. A árvore pode perguntar se a perda de pacotes passou de um limite e, depois, se a latência está alta. Cada resposta direciona para outro nó; a folha final representa a classe prevista.

É um bom ponto de partida porque as regras são fáceis de inspecionar. O risco é a árvore ficar profunda demais e memorizar particularidades dos dados de treino — o chamado overfitting, quando o modelo funciona bem nos exemplos conhecidos, mas piora em dados novos.

Interpretabilidade alta Baixa latência potencial Variância elevada

Como a árvore escolhe uma pergunta?

Critérios como o índice de Gini e a entropia estimam a mistura de classes em cada divisão. O algoritmo procura uma divisão que deixe os grupos resultantes mais homogêneos. A poda ou limites de profundidade ajudam a evitar árvores excessivamente complexas.

Impureza de Gini Gini = 1 − Σ pᵢ² Quanto mais próximo de 0, mais pura é a divisão.
02 BAGGING · MODELO DE CONJUNTO

Random Forest

Em vez de confiar em uma única árvore, combinamos as previsões de muitas.

A Random Forest treina árvores com diferentes amostras bootstrap — amostras obtidas por sorteio com reposição — e considera subconjuntos aleatórios de atributos. Esse processo é chamado bagging (agregação de modelos treinados em amostras diferentes).

Na classificação, as árvores votam e a categoria mais votada vence. Como as árvores não são idênticas, a combinação tende a reduzir a variância em relação a uma árvore isolada. Ainda assim, muitas árvores podem exigir mais memória e tornam a decisão completa menos simples de explicar.

Robustez Boa opção para dados tabulares Importância dos atributos
BAGGING: TREINAR EM PARALELO E VOTAR

Figura 2. Esquema conceitual de bagging. Três árvores são apenas uma ilustração, não a configuração final do experimento.

Quando vale considerar?

Quando queremos um baseline mais estável em dados tabulares, com várias medições relacionadas. A importância dos atributos pode ajudar a investigar quais variáveis mais influenciam as previsões, mas não prova causalidade.

03 BOOSTING · APRENDIZADO SEQUENCIAL

XGBoost

Cada nova árvore tenta melhorar o conjunto construído até então.

XGBoost significa eXtreme Gradient Boosting. É uma implementação otimizada de gradient boosting: árvores são adicionadas em sequência para corrigir erros residuais das previsões anteriores. O algoritmo usa otimizações computacionais e regularização, que penaliza modelos excessivamente complexos.

A taxa de aprendizado controla o tamanho da contribuição de cada nova árvore. Passos menores podem exigir mais rodadas; rodadas demais ou árvores profundas podem causar overfitting. A parada antecipada (early stopping) pode interromper o treino quando a métrica de validação deixa de melhorar.

Potencial preditivo alto Exige ajuste Treino sequencial
BOOSTING: CORRIGIR EM SEQUÊNCIA

Figura 3. No boosting, as árvores são adicionadas sequencialmente. O desenho resume a ideia, não os cálculos internos do algoritmo.

Quando vale considerar?

Quando o objetivo é obter desempenho preditivo forte em dados tabulares e há tempo para ajustar hiperparâmetros com uma validação separada. Não é correto afirmar que o XGBoost sempre vence: o resultado depende dos dados, das métricas e do ajuste.

O preditor de redes NetPulse

O sistema considera medições de conectividade para reconhecer possíveis degradações e priorizar a investigação.

Proporção de pacotes enviados que não chegam ao destino.

∿

✓

!
O erro mais perigoso pode ser o problema que o modelo não detecta.

O cenário do grupo define o falso negativo de risco ou falha como crítico: uma instabilidade não detectada pode impedir uma ação preventiva. Alertas falsos também importam, mas tendem a gerar verificações adicionais. Por isso, o recall da classe de risco deve receber atenção especial, junto do F1-score e da latência de inferência.

EXPERIMENTO DIDÁTICO · DADOS SINTÉTICOS

O que foi simulado e o que os resultados mostram

Para compreender como os três algoritmos podem ser comparados, propomos um experimento com 5.000 amostras artificiais de monitoramento de rede. Cada amostra contém latência, perda de pacotes, jitter e disponibilidade. Os modelos devem classificar cada situação como Estável, Em Risco ou Com Falha.

Configuração proposta 5.000 amostras sintéticas; 4.000 para treinamento e 1.000 para teste; semente aleatória fixa em 42.
Métricas avaliadas Acurácia, precisão macro, recall macro, F1-Score macro, tempo de treinamento e tempo médio de previsão por amostra.
Objetivo Entender os compromissos entre qualidade das classificações, velocidade e interpretabilidade.
Limitação Os dados são artificiais e não comprovam o desempenho do NetPulse em uma rede real.
PYTHON · EXEMPLO DE AVALIAÇÃO 

import time
import numpy as np
import pandas as pd

from sklearn.model_selection import train_test_split
from sklearn.preprocessing import LabelEncoder
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score
)
from xgboost import XGBClassifier

# 1. Gerar dados sintéticos e reproduzíveis
rng = np.random.default_rng(42)
n = 5000

latencia = np.clip(
    rng.gamma(2.2, 22, n), 1, 300
)
perda = np.clip(
    rng.beta(1.2, 10, n) * 100, 0, 100
)
jitter = np.clip(
    rng.gamma(1.8, 7, n), 0.1, 100
)
disponibilidade = np.clip(
    100 - perda * 0.7 + rng.normal(0, 1.8, n),
    70, 100
)

X = pd.DataFrame({
    "latencia_ms": latencia,
    "perda_pct": perda,
    "jitter_ms": jitter,
    "disponibilidade_pct": disponibilidade
})

# 2. Criar classes didáticas por regras
risco = (
    (latencia > 100).astype(int)
    + (perda > 3).astype(int)
    + (jitter > 25).astype(int)
    + (disponibilidade < 96).astype(int)
)

y = np.where(
    risco >= 3, "Com Falha",
    np.where(risco >= 1, "Em Risco", "Estável")
)

# Introduzir 3% de ruído nos rótulos
mascara = rng.random(n) < 0.03
classes = np.array(["Estável", "Em Risco", "Com Falha"])

for i in np.where(mascara)[0]:
    y[i] = rng.choice(classes[classes != y[i]])

# 3. Mesma divisão para todos os modelos
X_treino, X_teste, y_treino, y_teste = train_test_split(
    X, y, test_size=0.20,
    random_state=42, stratify=y
)

encoder = LabelEncoder()
y_treino_num = encoder.fit_transform(y_treino)

modelos = {
    "Árvore de Decisão": DecisionTreeClassifier(
        max_depth=8, random_state=42
    ),
    "Random Forest": RandomForestClassifier(
        n_estimators=100, max_depth=12,
        random_state=42, n_jobs=1
    ),
    "XGBoost": XGBClassifier(
        n_estimators=100, max_depth=5,
        learning_rate=0.1,
        subsample=0.9, colsample_bytree=0.9,
        objective="multi:softprob",
        eval_metric="mlogloss",
        random_state=42, n_jobs=1,
        tree_method="hist"
    )
}

resultados = []

for nome, modelo in modelos.items():
    # Treinamento
    inicio = time.perf_counter()

    if nome == "XGBoost":
        modelo.fit(X_treino, y_treino_num)
    else:
        modelo.fit(X_treino, y_treino)

    tempo_treino = time.perf_counter() - inicio

    # Previsão e medição repetida
    modelo.predict(X_teste.iloc[:10])
    repeticoes = 100

    inicio = time.perf_counter()
    for _ in range(repeticoes):
        previsoes = modelo.predict(X_teste)

    tempo_previsao = (
        time.perf_counter() - inicio
    ) / (repeticoes * len(X_teste)) * 1000

    if nome == "XGBoost":
        previsoes = encoder.inverse_transform(
            previsoes.astype(int)
        )

    resultados.append({
        "Modelo": nome,
        "Acurácia (%)": round(
            accuracy_score(y_teste, previsoes) * 100, 2
        ),
        "Precisão macro (%)": round(
            precision_score(
                y_teste, previsoes,
                average="macro", zero_division=0
            ) * 100, 2
        ),
        "Recall macro (%)": round(
            recall_score(
                y_teste, previsoes,
                average="macro", zero_division=0
            ) * 100, 2
        ),
        "F1 macro (%)": round(
            f1_score(
                y_teste, previsoes,
                average="macro", zero_division=0
            ) * 100, 2
        ),
        "Treinamento (s)": round(tempo_treino, 4),
        "Previsão (ms/amostra)": round(tempo_previsao, 6)
    })

print(pd.DataFrame(resultados).to_string(index=False))

Trecho ilustrativo: pressupõe que modelo, X_test e y_test estejam definidos. A variável y_pred é criada pela previsão. O exemplo pressupõe que a classe positiva represente risco ou falha. Ajuste average conforme o formato dos rótulos.

NOSSA RECOMENDAÇÃO

Escolher com evidências, não por fama.

Para o NetPulse, a primeira etapa é usar a Árvore de Decisão como baseline interpretável e comparar seu comportamento com Random Forest e XGBoost sob as mesmas condições. A escolha final precisa priorizar o recall da classe de risco sem ultrapassar o limite operacional proposto de 5 ms por amostra.

Se a Random Forest reduzir falsos negativos com latência aceitável, pode oferecer um equilíbrio prático. Se o XGBoost trouxer ganho consistente no recall/F1 sem exceder a latência, pode ser preferível. Se a árvore simples atingir os requisitos e a auditabilidade for decisiva, sua simplicidade pode justificar a escolha.

Critérios de decisão Recall de risco → F1-score → latência ≤ 5 ms → interpretabilidade
